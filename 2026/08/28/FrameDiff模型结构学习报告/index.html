1. 模型一句话概括

FrameDiff 是一个用于蛋白质 backbone 生成的 SE(3) 扩散模型。它不直接在所有原子坐标上做普通欧氏扩散，而是把每个残基表示成一个刚体 frame：

一个长度为 N 的蛋白 backbone 就是 N 个残基 frame 的序列：

扩散过程负责把真实 backbone frame 加噪成随机 frame；神经网络负责从带噪 frame 中预测去噪方向，也就是旋转 score 和平移 score；最后再用预测 frame 和 psi 扭转角重建 N、CA、C、O 等 backbone 原子坐标。

1.1 论文中的问题设定与贡献

论文把目标限定在 de novo protein design 中的 protein backbone generation：生成一个新的 backbone，之后要能找到一条氨基酸序列折叠到这个结构。作者强调，backbone 生成难点不只是几何坐标像不像蛋白，还要满足两类约束：

  • 物理/化学约束：键长、键角、原子排斥、链连续性等不能明显违规；
  • designability 约束：生成的 backbone 需要存在可设计序列，后续通过 ProteinMPNN + ESMFold/OmegaFold 的 self-consistency 来评估。

论文的核心贡献不是“发明一个新的 Transformer”，而是把蛋白 backbone 的 frame 表示、Riemannian score-based diffusion、SO(3)/R3 分解扩散、SE(3) 不变性约束和 AF2 Structure Module 风格的网络统一到一个可训练框架里。作者在第 1-2 页指出，已有方法如 RFdiffusion 在实践上很强，但依赖启发式 denoising loss 和结构预测预训练；FrameDiff 的目标是提供一个更 principled 的 SE(3) diffusion 框架，同时不依赖昂贵预训练。

3.4 节点、边与 mask

一个蛋白被模型看成残基图：

  • node: 单个残基，形状大致为 [B, N, D_node]
  • edge: 残基对 (i, j)，形状大致为 [B, N, N, D_edge]
  • res_mask: 哪些位置是真实残基，哪些是 padding
  • fixed_mask: 哪些位置固定不扩散；无条件生成中通常全 0
  • diffuse_mask = (1 - fixed_mask) * res_mask: 哪些残基参与扩散和更新

4.3 为什么要做 center-of-mass projection

论文第 3.3 节解释了一个容易忽略但很重要的问题：在 \(\mathbb{R}^3\) 上不存在一个真正平移不变的概率分布，因此如果直接在 \(\mathrm{SE}(3)^N\) 上要求完整的全局旋转/平移不变性，会遇到理论障碍。作者的解决方式是把所有残基的平移坐标保持在质心为 0 的子空间中：

也就是将平移部分投影到 centered SE(3)^N。代码里这个思想体现在两处：

  • 数据预处理时，parse_chain_feats 会用 CA 坐标中心做居中；
  • 反向采样时，R3Diffuser.reverse(..., center=True) 会在每一步去掉 center of mass。

这样做的效果有两层：

  • 理论上，模型输出分布可以对应到全局 SE(3) 不变的 backbone 分布；
  • 工程上，训练损失方差更小，因为网络不用为任意整体平移学习等价的结构。

10.4 pairwise distance auxiliary loss

当 t < dist_mat_loss_t_filter 时启用，默认也是 0.25。

它比较原子之间的 pairwise distance，且只关注真实距离小于 6 Å 的近邻关系：

这能鼓励局部空间关系更合理，减少结构断裂和碰撞。

论文中说明，单独使用 DSM 时模型能学到较合理的粗粒度拓扑，但会出现细粒度物理问题，例如 chain breaks 和 steric clashes。因此作者加了两个 auxiliary losses：

  • \(L_{bb}\): 直接惩罚 N、CA、C、O backbone 原子坐标误差；
  • \(L_{2D}\): 惩罚近邻原子之间 pairwise distance 的误差，只覆盖真实距离小于 0.6 nm，也就是 6 Å 的原子对。

这两个损失只在 \(t < 0.25\) 时使用，因为此时扩散噪声较低，细节几何已经开始显现，监督原子级几何才更有意义。

10.5 训练数据、batching 和优化设置

论文附录 J.1 提供了实验训练设置：

  • 训练数据来自 PDB，下载日期为 2021-08-08；
  • 只取 monomer，长度范围 60-512，分辨率小于 5 Å；
  • 初筛得到 23,913 个蛋白；
  • 再用 DSSP 过滤掉 loop composition 大于 50% 的结构，最终 20,312 个蛋白；
  • 作者认为去掉高 loop 比例结构改善了训练和样本质量；
  • 网络训练约 2 周，硬件为 2 张 A100，优化器为 Adam，学习率 1e-4，beta1=0.9，beta2=0.999。

还有一个容易被忽略的工程细节：FrameDiff 使用 fully connected residue graph，因此 memory 随 \(N^2\) 增长。论文的 TimestepBatch 策略不是把很多不同长度蛋白硬拼到一个 batch，而是对同一个 backbone 采样多个不同时间点的扩散实例，使 batch 内长度一致，并用最大边数阈值控制显存。仓库当前代码的 TrainSampler/length_batching 也体现了按长度和 max_squared_res 控制 batch 的思路。

15. 论文实验与消融结果

这一节不是网络结构本身，但对理解“哪些结构设计真的重要”很有价值。

15.1 评价指标

论文第 5.1 节主要用三类指标评估生成 backbone：

  • designability：先用 ProteinMPNN 为生成 backbone 设计多条序列，再用 ESMFold 预测这些序列的结构，最后比较预测结构和生成 backbone 的一致性；
  • diversity：用 MaxCluster 按 TM-score 阈值聚类，报告 unique clusters / samples；
  • novelty：用 FoldSeek 在 PDB 中找最相似结构，报告最高 TM-score，记作 pdbTM。

designability 又有两个指标：

15.2 主结果：noise scale 和采样设置的影响

论文 Table 1 比较了不同采样噪声 \(\zeta\)、反向步数 \(N_{steps}\) 和每个 backbone 设计序列数 \(N_{seq}\) 的效果：

noise scale zeta N_steps N_seq scTM > 0.5 scRMSD < 2 Å diversity
1.0 500 8 49% 11% 0.75
0.5 500 8 74% 23% 0.56
0.1 500 8 75% 28% 0.53
0.1 500 100 84% 40% 0.54
0.1 100 8 74% 24% 0.55

可以读出几个结论：

  • 降低采样噪声 \(\zeta\) 明显提升 designability，但会牺牲一部分 diversity；
  • 增加 \(N_{seq}\) 会提高 self-consistency 通过率，因为每个 backbone 有更多序列设计尝试；
  • \(N_{steps}=100\) 时仍能得到 74% 的 \(\mathrm{scTM} > 0.5\)，论文报告 100 aa backbone 在 A100 上生成约 4.4 秒，速度相对 RFdiffusion 的公开报告快一个数量级以上。

15.3 消融：哪些模块最关键

论文 Table 2 使用 \(\zeta=1.0, N_{steps}=500, N_{seq}=8\) 做消融。结果可以整理为：

设置 scTM > 0.5 解读
self-conditioning + L2D + Lbb + Ldsm 49% 完整模型
self-conditioning + L2D + Lbb + LF 39% 用 Frobenius rotation loss 替代 DSM，下降 10 个百分点
L2D + Lbb + Ldsm 42% 去掉 self-conditioning，下降 7 个百分点
Lbb + Ldsm 22% 去掉 pairwise distance loss，下降明显
Ldsm only 16% 只用 DSM，细粒度几何不足
self-conditioning + L2D + Lbb, no Ldsm 0% 没有 score matching 主损失时模型不可用

这张消融表给网络结构学习带来三个重点：

  • \(L_{dsm}\) 是核心学习信号，没有它无法学习正确反向扩散；
  • auxiliary losses 对 backbone 几何质量非常重要，尤其能减少 chain breaks 和 steric clashes；
  • DSM rotation loss 比 Frobenius rotation loss 更符合理论，且实验中 designability 更高。

15.4 与其他方法的关系

论文第 6-7 节的定位比较克制：FrameDiff 并不声称全面超过 RFdiffusion。作者强调不同方法的训练数据和评估流程差异很大，因此不能简单下 SOTA 结论。更准确的定位是：

  • 相比 FoldingDiff：FrameDiff 在论文附录 J.5 的同数据设置下明显更强，\(\mathrm{scTM} > 0.5\) 从 6% 到 60%；
  • 相比 Chroma：FrameDiff 的理论框架更偏 SE(3) frame diffusion，但实验设置不同，不能直接一锤定音；
  • 相比 RFdiffusion：FrameDiff 参数量约为 RFdiffusion 的 1/4，不依赖蛋白结构预测预训练，但 designability 仍低于 RFdiffusion 的公开表现。

15.5 论文作者明确指出的未来方向

作者在 Discussion 和附录 J 中提到几个后续方向：

  • 扩展到 conditional generation，例如 sequence-to-structure、motif scaffolding；
  • 扩展到更大蛋白和 multimer；
  • 使用更大数据和更好优化来缩小与 RFdiffusion 的 designability 差距；
  • 提升长蛋白，尤其 400 aa 以上的严格 \(\mathrm{scRMSD} < 2\ \mathrm{\AA}\) designability；
  • 在一般 Lie group 任务上复用 Brownian motion + DSM + subgroup invariance 的理论框架，例如 robotics 中的 SO(3)。

17. 各模块的学习重点

如果你要系统学习这个模型，建议按下面顺序读：

  1. 先读 ScoreNetwork.forward：理解输入输出字段，不要一开始陷入 SO(3) 数学。
  2. 再读 Embedder.forward：看清 node/edge 特征如何构造。
  3. 读 IpaScore.forward：掌握主干 block 的执行顺序。
  4. 读 InvariantPointAttention.forward：这是最核心、最复杂的结构模块。
  5. 读 SE3Diffuser.forward_marginal 与 reverse：理解训练加噪和采样去噪。
  6. 最后读 loss_fn：把网络输出和训练目标对应起来。

18. 这个模型结构的优点

  • 用 SE(3) frame 表示 backbone，比直接生成原子坐标更贴合蛋白几何。
  • 旋转和平移分别在合适空间扩散：\(\mathrm{SO}(3)\) 处理旋转，\(\mathbb{R}^3\) 处理坐标。
  • IPA 能把序列表示、pair 表示和三维几何统一进 attention。
  • BackboneUpdate 每一层都更新 frame，使网络可以像 AlphaFold Structure Module 一样迭代修正结构。
  • self-conditioning 给模型提供上一轮预测的结构先验，通常能改善采样稳定性。

19. 需要注意的局限

  • 该模型主要生成 backbone，不直接生成完整 sidechain。
  • 默认训练数据过滤偏向单体蛋白，长度范围和结构分布受配置影响。
  • SO(3) 扩散依赖预计算 IGSO(3) 表格，理解和修改时要注意缓存。
  • 代码 README 也提到作者计划重构 score framework 以更贴近论文数学，因此当前实现有些地方更像工程实现而不是论文公式的直译。
  • 平移损失在当前默认配置下基本使用 x0 loss 分支，这一点和“纯 score matching”的直观说法略有差异，读代码时要特别留意。
  • 由于 fully connected graph 的复杂度是 \(O(N^2)\)，长度扩展会直接带来显存压力。
  • 严格 designability 指标 \(\mathrm{scRMSD} < 2\ \mathrm{\AA}\) 在长蛋白上仍是短板，论文附录 J.4 指出 400 aa 以上仍有明显改进空间。
  • novelty 主要是计算评估，作者也提醒真正的新蛋白功能和稳定性仍需要实验表征。

21. 记忆版总结

FrameDiff 的网络可以记成四句话：

  1. 每个残基先被表示成一个 SE(3) 刚体 frame，而不是一堆自由原子坐标。
  2. 前向过程分别给 frame 的旋转和平移加噪，得到 rigids_t。
  3. 去噪网络用 IPA + sequence Transformer + frame update 反复更新残基表示和 frame。
  4. 输出的 frame、旋转/平移 score 和 psi 角共同恢复最终 backbone。

最核心的结构不是普通 Transformer，而是 IpaScore 中反复堆叠的 IPA block。IPA 让 attention 同时看见三件事：残基自身特征、残基对特征、当前三维空间位置关系。这正是它能用于蛋白 backbone 生成的关键。
